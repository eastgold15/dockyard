# 画布 client 模式（世界地图）

dockyard 画布是框架里交互最复杂的页面（拖拽、连线、实时状态、部署抽屉、容器终端）。它经历了三个阶段：

1. **React 岛阶段**：htmx 壳 + 岛容器 + `htmx.ajax` 桥调服务端片段模态——754 行抽屉片段靠桥维护，成本过高
2. **整页 React client 阶段**：岛、桥、afterSwap 挂载器全部删除，模态/表单/错误回显一套模型
3. **Solid + 世界地图阶段（现行）**：React 弃用（VDOM 黑盒违背产物可审查哲学，见 [lowering](./lowering.md)）；画布语义从「项目边界」反转为「物理世界地图」

## 世界地图语义

**物理层恒定，项目是透镜**：

- `canvas_nodes` 一台服务器全库一张卡（`serverId` 唯一，无 projectId）；本机也是一张卡
- `/canvas` 默认世界地图：全部服务器 + 全部项目的部署目标；`?project=X` 是**过滤透镜**——非本项目卡片完全隐藏，只剩空服务器卡（物理事实仍在）
- 一个项目可以跨多台服务器，跨服依赖边在世界地图上自然呈现
- 画布分**本机/远程两区**（`server.local` 由 host 是否 loopback 派生），中间分界线——后期演化为部署通道（本机构建 → 产物推远程）
- 建内容操作（部署本仓库/添加数据库/新建分组）只在透镜激活时可用——世界视图是观察层，创建必须知道项目归属

### 发现层（只读）

服务器上 docker 里跑着、但不归 dockyard 管的容器，也会画在服务器卡内（虚框 + 「发现」徽章）。

- **发现 ≠ 纳管**：发现卡没有部署/回滚/备份/删除入口，拖拽即弹回原位、位置不落库；点卡片只开只读详情弹窗（镜像/容器 ID/端口/归属，可复制 ID），纳管仍走「部署本仓库/添加数据库」
- **过滤口径**：排除 `dockyard.managed=true` 的容器（已有卡片）与 compose 一次性容器（`com.docker.compose.oneoff=True`）
- **项目归属**按 compose 的 `working_dir` 反查 `projects.localPath`（最长前缀胜出）；兜底依次为 `dockyard.project` 标签 → compose project 名 → 容器名前缀。匹配不到 `projectId=null`，只在世界视图出现
- **数据是快照 + 变更触发重拉**：卡片由 `/board` 现查（`docker.listContainers({all:true})`，本机走本地 socket、远程经 SSH）；container-poller 每轮对未纳管容器算 `id:state` 指纹，变化时推无载荷 `discovery` 事件 → client 重拉 `/board`（发现卡本身不进 SSE 细粒度 store）。docker 未检测/报错 → 空数组，不阻塞画布
- 纯函数在 `discovery.ts`（`matchProjectId`/`portsSummary`/`discoverContainers`），单测不依赖 docker

## 结构

```
src/pages/canvas/
  client/               # 整页 Solid（@elysiax/solid 预打包 → .elysiax/shells/canvas.client.js）
    index.tsx           # render() 挂载
    app.tsx             # 透镜选择器（?project= 初始透镜）+ UiContext + LiveProvider + DrawerHost
    board.tsx           # 世界地图：结构 fetch + 透镜过滤 + 本机/远程分区
    live-provider.tsx   # 唯一 SSE 连接 + live store（必须罩住 Board 与 DrawerHost）
    flow.test.tsx       # client 测试样例（happy-dom + solid render，bunfig [test].preload）
    nodes.tsx           # 卡片视图（部署/删除/尺寸持久化/项目徽章）
    drawers.tsx         # 抽屉/弹窗（向导/服务抽屉/日志/域名/变量）
    console.tsx         # xterm ←→ WS
    live.ts             # SSE → LiveContext（Solid store，accessor 订阅）
    lens.ts             # 透镜模块级信号（app/board/nodes 三处平级消费）
    api.ts              # Eden Treaty 客户端 + routes.gen 路径助手
    ui.ts               # UiBus（open/close/refresh）模态总线
  canvas.actions.ts     # JSON API（/api/canvas/*）：board/SSE/CRUD（全部全局，无 :projectId）
  canvas.service.ts / canvas.repository.ts / canvas.model.ts
  discovery.ts          # 发现层纯函数（未纳管容器 → 卡片模型，按项目 localPath 归属）
  canvas.di.ts
```

## 三条数据通道

| 通道 | 内容 | 传输 | 更新时机 |
| --- | --- | --- | --- |
| 结构数据 | 卡片/连线/位置（nodes/edges） | `GET /api/canvas/board` JSON（全局） | 挂载拉一次 + body `refresh` 事件 refetch |
| 节点几何 | 拖拽/拉伸中的位置尺寸 | **本地权威**（Solid signal） | 合并时保留 `dragging` 节点 |
| 实时数据 | 部署状态、容器 state | SSE `/api/canvas/events`（全局频道） | 服务端 publish 即推，进 LiveContext store |

**首帧是全量快照，不是空流**：订阅即收到「最近一次部署状态（含 stage）」+「全部容器 state」，不必先等下一轮 diff。否则刷新页面后已部署的卡会短暂显示「未部署」（SSE 已连上，但还没人推事件）。快照要在请求作用域内**先取出服务**再闭包使用——`di` 随请求结束释放，异步快照跑完再 `di.get` 会撞 `Container is disposed`。

为什么分开：

- **结构不进 SSE**：位置/连线是低频高价值数据，走 REST + 按需 refetch，不会因为一条状态推送把用户正在拖的节点重渲染掉
- **实时不进 node.data**：状态灯这类高频数据进 Solid store 的细粒度订阅（`live().status` accessor），不触发 nodes 数组重算
- **refresh 事件是约定**：结构变更后 `document.body.dispatchEvent(new Event("refresh"))`，board 监听重拉

两条与「状态归属」有关的纪律：

- **Provider 作用域 = 消费方全集**：live store 建在 `LiveProvider`（App 层），`Board` 与 `DrawerHost` 都在其下。只包 Board 的后果是抽屉拿到 context 默认值 `emptyLive`——节点实时、抽屉永远不许动。`LiveProvider` 同时是 discovery 帧 → `refresh` 事件的派发点
- **状态帧带 `runId`**：日志抽屉看的是某一条 run 的日志，实时 status 只在 `live().runId === 该 run.id` 时才敢覆盖徽章，否则当前新 run 的 `building` 会冒充历史 run 的状态。快照帧也带 runId；终态（success/failed）在合并时直接推导 `running=false`——服务端对已结束的 run 只发 status，不推导就会在断线重连后永久停在「部署中」

## 自研 flow 基座（已升舱 `@elysiax/flow`）

画布基座已升舱为框架包 `packages/flow`（`@elysiax/flow`）：纯 DOM + SVG 实现（panzoom/拖拽/连线/拉伸全部透明指针事件，无 VDOM 无 d3）。主题色走 CSS 变量（`--flow-dot`、`--flow-handle-bg` 等，带 fallback），行为钩子是结构属性（`data-nodrag`、`data-flow-menu`、`data-handle-id`）。两个踩过的坑：

1. **`<For>` 按引用渲染会把被拖节点 DOM 重建**——拖拽每帧 `setNodes` 换新对象 → 指针捕获丢、拖拽断成"每次只动一点"。解法：节点按 id 进 `createStore` + `reconcile` 原地合并，代理引用稳定，DOM 不重建；store 要同步初始化（首帧 `createEffect` 还没跑，异步初始化会 undefined 崩溃）
2. **整页壳没有 AppLayout**：`h-full` 高度链在 `#root` 断掉（画布 0 高、fitView 算出 minZoom）。根组件必须自带 `h-screen`

指针语义（框架层保证）：

- **pointercancel 也是收尾**：手势被系统夺走（触屏接管/失焦）走 `onNodeDragStop(node, true)`，调用方必须回滚位置并放开门闩；只清状态的写法会让「交互中」永久为真、结构刷新全部被压住
- **平移是增量累加**：滚轮在拖拽/平移中途缩放时，节点拖拽基准会重建（`rebaseActiveGesture`），平移本身因只记上一次坐标而天然免疫——存「起手坐标」的写法会在缩放后把视口跳回去
- **平移后的 click 不算点空白**：超过 3px 的平移会抑制松手后的 click，不误清选中

## client 测试约定

client/ 是浏览器代码，bun test 直接跑有两个坑，都有既定解法：

1. **Solid JSX 不是 React JSX**：自动运行时找不到 `solid-js/jsx-runtime` 的 `jsx` 导出——Solid 必须经 babel-preset-solid 编译。`@elysiax/solid/testing` 的 `setupClientTest()` 在测试进程挂与构建同一套 `solidPlugin`（测试里所有 .tsx 按 Solid 编译）。
2. **solid-js/web 默认解析到 server build**：bun test 不带 browser 条件会拿到 server.js 抛 "Client-only API"。解法：测试命令带 `--conditions=browser`。

落地三件套（dockyard 已配好，可直接抄）：

```toml
# bunfig.toml
[test]
preload = ["./test/preload.ts"]
```

```ts
// test/preload.ts
import { setupClientTest } from "@elysiax/solid/testing";
// htmx + Solid 混用应用必须收窄 filter：@kitajs/html 语义的 .tsx（如 @workspace/htmx
// 的 toast.tsx）被 Solid 编译会注入 solid-js/web 而解析失败。
// 放行「本应用 client/」+ flow 包——link: 装进来时路径可能是包名也可能是真实目录，两个都写。
setupClientTest({
  filter: /(apps\/myapp\/src\/pages\/.*\/client|(packages\/flow|@elysiax\/flow)\/src).*\.tsx$/,
});
```

`setupClientTest` 另做了 **runtime peer 去重**：`Bun.plugin` 的 `onResolve` 在 `bun test` 运行时不生效，link: 引入的 `@elysiax/flow` 会从自己的 `node_modules` 拿到另一份 solid-js。两份实例的响应式图互不相通——外部 props 变了、flow 内部 DOM 纹丝不动，测试静默通过。现在用 `bun:test` 的 `mock.module` 把 `solid-js` / `solid-js/web` / `solid-js/store` 钉到应用根副本，和浏览器构建保持同一实例。

```json
// package.json
"devDependencies": { "@happy-dom/global-registrator": "…" },
"scripts": { "test": "bun test --conditions=browser" }
```

测试文件放组件旁边（`*.test.tsx`，无需 jsx pragma——编译走插件）。只断 DOM 结构与行为钩子（data-* 属性、文本），不断样式像素。样例见 `client/flow.test.tsx`。

**服务端 repository 测试**（非 client，另一套约定）：内存 sqlite 跑真迁移——`new Database(":memory:")` + `PRAGMA foreign_keys = ON`（FK cascade 行为必须真实）+ `migrate(db, migrationsJournal)`，journal 从 `shared/migrations-journal.ts` 引（与生产同一份聚合，跨原子 import 只能落 shared）。裸 SQL 造上游行时注意 drizzle `$defaultFn` 列要手工给值。样例见 `deploy/deploy.repository.test.ts`——它就靠这套抓住了一个潜伏 bug：0011 迁移的 `groupId REFERENCES service_groups(id)` 是悬空外键（真名 canvas_groups），老库因改名历史无恙，全新装库 FK ON 下插入必炸。

## 浏览器打包铁律

client/ 是浏览器代码，Bun 打包时依赖链里**任何 Node-only 包都会让页面 500**：

- **dotenv**：browser dist 里 `require("child_process")`，直接炸。解法：env 文本函数抽零依赖模块转出口
- **.elysiax 桶文件**：会把服务端图谱（bun:sqlite）打进 bundle。routes 必须直接引 `.elysiax/routes.gen`（doctor 检查）
- 类型 import 随意——会被擦除，不进 bundle
