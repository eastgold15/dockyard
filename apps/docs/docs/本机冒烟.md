# 本机部署冒烟手册

改动部署链路（pipeline/forms/归属标签/回滚/运行时对账）之后，用本手册在**本机**把六阶段真实跑一遍：不碰真实数据、不动他人容器，跑完即清。

## 1. 隔离运行环境

dockyard 的数据目录走 XDG，沙盒用一次性目录即可（数据库、仓库缓存、备份、relay 全部落里面）：

```bash
mkdir -p /tmp/dockyard-smoke/{data,cache}
cd apps/dockyard   # 必须在包目录里跑：根 tsconfig 没有 jsxImportSource，从仓库根起会报 react/jsx-dev-runtime 找不到
XDG_DATA_HOME=/tmp/dockyard-smoke/data XDG_CACHE_HOME=/tmp/dockyard-smoke/cache \
  bun src/index.ts   # 端口硬编码 3003
```

- **停服务按监听端口找 PID**：`ss -ltnp | grep ':3003'` 然后 kill 那个 bun 进程。`nohup … & echo $!` 记下的可能只是外层 shell，杀完端口还占着；`pkill -f 'bun src/index.ts'` 又会匹配到执行它的 shell 自己（也别忘了 `bun --watch` 会拉起子进程）
- `ensureDirs()` 必须同步执行：`db.ts` 在模块顶层打开 SQLite，异步建目录会和打开形成竞态（全新 XDG 目录上直接 `unable to open database file`）

## 2. 准备被测项目

一个最小目录即可：`Dockerfile` + `docker-compose.yml`（含 `ports` 与可写探针文件），例如 app 把版本号写进 `/opt/version`，用来验证「重部署后容器真的是新镜像」。

**不启 API 的最小验证（改模板/标签时先跑这个）**：把 `dbCompose(type, name, { targetId, project })` 的产物写到临时目录，`docker compose config` 看解析出的 `name` / `container_name` / `labels`，再 `docker compose create`（只创建不启动，避开端口冲突）用 `docker inspect` 核对 `com.docker.compose.project` 与 `dockyard.*` 标签，最后 `docker compose -p <项目名> down -v` 清掉。

## 3. 走一遍六阶段

1. 画布上右键服务器卡 →「部署本仓库」→ 选**本地文件夹导入**，指向被测目录
2. 观察抽屉与步骤条：源 → 构建 → 传输 → 运行 → 暴露 → 产物
3. 部署完成后核对：
   - `docker inspect <容器> --format '{{json .Config.Labels}}'` 含 `dockyard.managed=true` 与 `dockyard.target-id=<id>`（否则下次 preflight 会把自家容器当别人的）
   - 抽屉 Deployments/Monitor/Console 均可用（容器名推导依赖部署回写的 compose 项目名）
   - 刷新页面后卡片仍显示「运行中」（SSE 首帧含部署状态快照）
4. **重部署**：改版本号再部署一次，确认容器内容真的更新（不是旧容器）
5. **回滚**：在部署历史里回滚到上一产物，确认内容回退
6. （可选）数据库实例：备份 → 改数据 → 恢复，确认恢复前安全备份已生成

### 3.1 API 直驱（可脚本化，不点 UI）

本机服务器（id=1）启动即自动认领，不需要建；前置：本机 sshd 可用且 `ssh 127.0.0.1` 免密。

```bash
B=http://127.0.0.1:3003
# 画布节点 + 本地项目（resolve-local 按路径幂等落库）
NODE=$(curl -s -X POST $B/api/canvas/nodes -H 'content-type: application/json' -d '{"serverId":1,"x":100,"y":100}' | jq -r .id)
PROJ=$(curl -s "$B/api/canvas/resolve-local?path=/tmp/fixture/hello-app" | jq -r .projectId)
# 应用目标（本地来源：构建在本机、镜像免传输）
curl -s -X POST $B/api/deploy/targets/app -H 'content-type: application/json' -d "{
  \"nodeId\":$NODE,\"projectId\":$PROJ,\"name\":\"hello-app\",\"branch\":\"main\",
  \"composePath\":\"docker-compose.yml\",\"remoteDir\":\"~/dockyard/hello-app\",
  \"services\":[{\"name\":\"web\",\"exposed\":false,\"env\":{}}],\"depIds\":[],\"reuse\":[]}"
curl -s -X POST $B/api/deploy/targets/1/deploy
# 轮询：GET /api/deploy/targets/1/log → .dep.status / .dep.stage / .dep.commitSha
# 数据库实例：POST /api/deploy/targets/db {"nodeId":1,"name":"smoke-pg","dbType":"postgres","remoteDir":"~/dockyard/smoke-pg"}（创建即部署）
# 备份/恢复：POST /api/deploy/targets/2/backup → POST /api/deploy/targets/2/restore {"file":"<备份名>","confirm":true}
```

核对点：`docker inspect <容器> --format '{{index .Config.Labels "com.docker.compose.project"}}'` 与 `servicesJson.project` 一致；改版本号重部署后 `curl 宿主端口` 内容真的变了；回滚后内容回退且 `servicesJson.project` 不被清空；恢复后数据回来、`backups/target-<id>/` 多出一份恢复前安全备份、`~/dockyard/restore/<id>/` 不留临时文件；`timeout 4 curl -sN $B/api/canvas/events > /tmp/sse.txt` 首帧依次是 `ping`、各目标 `status`（带 stage）、容器 `state`（`head -c` 直连会被缓冲卡住，必须重定向到文件）。

## 4. 已知坑（都会伪装成「功能坏了」）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 同 tag 重建镜像后部署，容器还是旧代码 | `compose config` 哈希只看镜像**名** | `up -d --force-recreate`（`composeUpCommand` 已统一） |
| 重部署被 preflight 拦截「非本工具管理的同名容器」 | 容器创建时没写归属标签，标签创建后不可变 | 删除旧容器重部署；新容器随 up 的 labels 层创建 |
| redis 镜像里新写入的文件被旧内容遮住 | redis 镜像 `VOLUME /data` 的匿名卷在 recreate 时被复用 | 探针写 `/opt`（卷外），或 `docker compose down -v` 后重试 |
| 刷新后已部署卡片显示「未部署」 | SSE 首帧原先只有容器状态 | 首帧已合并部署 status/stage 快照 |
| SSE 500 `Container is disposed (key: "containerPoller")` | 请求作用域释放后异步快照再 `di.get` | 请求内先取出服务再闭包使用 |
| `curl` 看不到 SSE 帧 | 输出缓冲；或连接被 Bun `idleTimeout`（默认 10s）先于 25s 心跳掐断 | 重定向到文件后再读；连上应立即收到 `event: ping` 握手帧，若 10s 后日志有 `timed out a request`，检查 `start()` 的 `idleTimeout`（默认 60s） |

## 5. 清理

```bash
# 容器/网络（在部署目录）
docker compose -p <项目名> down
# 冒烟产生的镜像 tag
docker images | grep 'dockyard-'      # 确认后删除 run-* / 冒烟专用名
# 远端目录与沙盒
rm -rf ~/dockyard /tmp/dockyard-smoke
```

**只删自己创建的**：本机可能有真实业务容器（如 tradeflow），冒烟全程不要动它们。清理完用 `docker ps -a` 复核。
